## 남은 Task와 착수 지점

### Task 18 — safety governor

migration 0018로 `automation_activity_ledger`(`(date, action)` 복합 PK와 `count`)를 추가하고,
`domain/settings.py`의 `safety_policy` kind(이미 정의돼 있고 기본값도 있음)를 실제로 읽어 판정합니다.

구현 위치와 이어붙일 지점이 이미 준비돼 있습니다.

- 판정 로직: `application/automation/governor.py`를 새로 만들고, `application/llm/budget.py`의
  `CallBudget`과 같은 형태(설정 읽기 + ledger 집계 + 상한 초과 시 stable code 예외)를 따르면 됩니다.
- 배치 연결: `application/automation/run_session.py`의 `RunSession.run()`이 글 하나를 처리하기 전에
  governor를 호출하도록 넣습니다. 중단 사유는 `domain/sessions.py`의 `ABORT_REASONS`에 이미
  `daily_cap_reached`, `outside_allowed_hours`, `consecutive_failures`가 들어 있습니다.
- 간격·jitter·체류: `RunSession`에 clock과 sleep을 주입해 fake clock으로 결정적으로 테스트합니다.
  `run_engagement.py`의 `monotonic` 주입 방식을 그대로 쓰면 됩니다.
- 알림: 중단 사유를 기존 SMTP digest로 보냅니다. `application/discovery.py`의 `SmtpDigestSender`가
  이미 있고 factory에서 구성됩니다.

주의: `safety_policy`의 `allowed_hours`는 정수 리스트이고 자정 넘김 경계를 테스트 요건이 요구합니다.

## 작업 방식 (이어받을 때 그대로 쓰면 됩니다)

1. `git fetch && git checkout -B feature/<주제> origin/main`
2. Task 하나를 PR 하나로 두고, 내부는 커밋으로 나눕니다. 최근 PR은 migration·저장소 → 실행·API →
   테스트 순서로 3~4커밋이었습니다.
3. 커밋 메시지는 Conventional Commits입니다. `commit-msg` hook과 CI의 `Commit convention` job이
   형식을 강제합니다.
4. PR 전 로컬 게이트: `uv run ruff format --check .`, `uv run ruff check .`, `uv run ty check`,
   `uv run pytest`, TypeScript 변경 시 `npm --prefix client run check`, 그리고 migration을 추가했다면
   wheel smoke.
5. `gh pr create` → `gh pr checks <번호> --watch` → 10개 job green이면 `gh pr merge <번호> --squash
   --delete-branch`.
6. 병합 후 계획 문서의 Task 상태·검증 결과·결정 로그를 갱신합니다.

## 반복해서 걸린 함정

- **`ty`는 `# type: ignore`를 존중하지 않습니다.** 테스트에서 가짜 객체를 넘길 때는 Protocol을 정의하고
  구조적으로 맞추세요. `dict`는 값 타입이 불변이라 `Mapping`을 써야 통과하는 경우가 있습니다.
- **migration head를 두 곳에서 함께 올려야 합니다.** `scripts/smoke_installed_wheel.py`의
  `EXPECTED_MIGRATION_HEAD`와 `tests/integration/infrastructure/test_app_settings_repository.py`의
  `HEAD`입니다.
- **새 설정 kind는 migration이 필요합니다.** `app_settings.kind`에 CHECK 제약이 있고 SQLite는 CHECK를
  제자리에서 바꿀 수 없어 table을 재작성해야 합니다. 0011·0012·0015가 그 예입니다.
- **새 endpoint는 `docs/api/openapi.yaml`에 함께 넣어야 합니다.** `tests/unit/api/test_contract.py`가
  FastAPI가 만든 operation 집합과 문서를 비교합니다. 문서에서 `application/problem+json`을 쓰는 응답은
  route에서도 `problem_metadata(...)`로 선언해야 합니다(FastAPI 기본 422는 `application/json`입니다).
- **page bundle에 probe를 추가하면** `client/src/page/index.ts`의 목록·버전,
  `infrastructure/browser/page_scripts.py`의 `PAGE_PROBES`·`BUNDLE_VERSION`,
  `client/tests/page/index.test.ts`의 기대 목록을 모두 갱신해야 합니다.
- **열린 SSE 스트림을 `TestClient`로 소비하면 무한 정지합니다.** `asyncio.run` +
  `httpx.ASGITransport`를 쓰거나 서비스 레벨 generator를 `asyncio.timeout`으로 검증하세요. 이 함정
  때문에 실제로 pytest가 한 시간 넘게 멈춘 적이 있습니다.
- **`gh pr create --body`에 backtick을 그대로 쓰면 shell이 명령으로 해석합니다.** Python heredoc으로
  `subprocess.run(["gh", ...])`를 호출하는 방식이 안전합니다.
