## 3. 이번 작업에서 실제로 찾아 고친 결함

문서화된 계획을 그대로 구현하는 것 외에, 검증 과정에서 드러난 실제 문제를 고쳤습니다. 다음
세션이 비슷한 종류를 찾을 때 참고하세요.

### 3.1 `uv run pytest`가 무한 정지 (PR #64)

`EngagementRunService.channel()`이 존재하지 않는 `run_id`에도 채널을 만들고 `events()`가 종료
조건 없이 `await queue.get()`을 반복했습니다. 여기에 starlette `TestClient`가
`portal.call(self.app, ...)`로 응답 완료까지 기다리며 body를 버퍼링해 `client.stream()` 진입
자체가 반환되지 않았습니다. `events()`가 저장소 조회로 분기하도록 고치고 keepalive·deadline·채널
회수를 넣었으며, `pytest-timeout`과 `--timeout=60 --timeout-method=thread`를 추가했습니다.

### 3.2 글 작성 화면에 도달할 방법이 없었음 (PR #77)

Task 16에서 만든 글쓰기 작업 공간이 **클릭으로 도달 불가능**한 상태였습니다. `showWriting()`을
호출하는 UI 요소가 없었고 `client/public/index.html`에 `<nav>`가 없었습니다. endpoint 16개가
구현돼 있는데 사용자에게는 닫혀 있었습니다.

### 3.3 세션 배치 승인이 동의를 확인하지 않았음 (PR #79)

글 하나 실행은 `403 consent_missing`으로 즉시 거부하는데, 여러 글을 처리하는 배치는 승인을
통과시킨 뒤 글마다 같은 사유로 실패했습니다. 거부하려고 대기열을 소모하는 셈이었습니다.
`RunSession.approve`에서 확인하도록 고쳤습니다. 이 결함은 새로 추가한 여정 테스트가 찾았습니다.

### 3.4 `openapi.yaml`의 settings kind enum 누락 (PR #79)

`llm_budget`·`writing_profile`이 `domain/settings.py`에는 있는데 문서 enum에는 없었습니다.
서비스는 dynamic dispatch라 동작했지만 계약 문서가 실제와 달랐습니다.

### 3.5 계획 문서의 잘못된 서술

"설정 kind는 migration 불필요"라고 적혀 있었으나 `app_settings.kind`의 CHECK 제약 때문에 table
재작성이 필요합니다. 고친 뒤 migration 번호를 한 칸씩 밀었습니다.

## 4. 반복해서 걸린 함정 (필수 준수)

다음 세션에서 같은 곳에 빠지지 않도록 적어 둡니다. 전부 실제로 시간을 잃은 지점입니다.

1. **`ty`는 `# type: ignore`를 무시합니다.** 테스트 가짜 객체는 Protocol로 구조적 일치시켜야
   합니다. `dict`는 값 타입이 불변이라 `Mapping`을 써야 통과하는 경우가 있습니다.
2. **migration head는 2곳에서 함께 올립니다.** `scripts/smoke_installed_wheel.py`의
   `EXPECTED_MIGRATION_HEAD`와 `tests/integration/infrastructure/test_app_settings_repository.py`의
   `HEAD`입니다.
3. **새 설정 kind는 migration이 필요합니다.** CHECK 제약 재작성이 필요합니다. 0011·0012·0015가
   예시입니다.
4. **새 endpoint는 `docs/api/openapi.yaml`에 반드시 추가합니다.**
   `tests/unit/api/test_contract.py`가 FastAPI 생성 operation 집합과 문서를 비교합니다. 문서에서
   `application/problem+json`을 쓰는 응답은 route에서도 `problem_metadata(...)`로 선언해야 합니다
   (FastAPI 기본 422는 `application/json`).
5. **FastAPI 생성 응답 코드 확인법**: `get_openapi(title=.., version=.., routes=app.routes)`로
   뽑아 문서와 맞춥니다. `app.openapi()`는 checked-in spec을 반환하므로 쓸 수 없습니다.
6. **page bundle에 probe 추가 시** `client/src/page/index.ts`(목록·`PAGE_BUNDLE_VERSION`),
   `infrastructure/browser/page_scripts.py`(`PAGE_PROBES`·`BUNDLE_VERSION`),
   `client/tests/page/index.test.ts`(기대 목록)을 모두 갱신합니다.
7. **열린 SSE를 `TestClient`로 소비하면 무한 정지합니다.** `asyncio.run` +
   `httpx.ASGITransport` 또는 서비스 레벨 generator + `asyncio.timeout`을 씁니다.
8. **`gh pr create --body`의 backtick은 shell이 해석합니다.** Python heredoc에서
   `subprocess.run(["gh", "pr", "create", ...])`로 호출합니다.
9. **`FakeBrowserDriver` 실패 주입은 실제 필드명을 확인해서 씁니다.**
   `page_navigation_failure`, `page.action_failures[selector]` 등입니다.
   `page_type_failure` 같은 이름은 없습니다.
10. **`BrowserSessionStatus`는 domain 규칙이 있습니다.** `state`가 `READY`가 아니면
    `open_pages`는 0이어야 하고 `login`은 관찰 불가여야 합니다. 가짜 객체를 만들 때 걸립니다.
11. **ruff line-length 100.** 모듈 docstring이 자주 초과합니다.
12. **`A && B ; C` 형태의 shell 체이닝 주의.** `A`가 실패하면 `B`는 건너뛰지만 `C`는 실행됩니다.
    이 때문에 브랜치 생성이 건너뛰어지고 커밋이 `main`에 올라간 적이 있습니다. 커밋 전
    `git status -sb`로 현재 브랜치를 확인하세요. (복구는 `git branch <name>` →
    `git branch -f main origin/main`으로 했습니다.)

## 5. 구조 요약 (다음 작업에 필요한 지점)

### 5.1 실행 흐름

- `application/automation/run_session.py`의 `RunSession.run()`이 글 하나를 처리하는 루프입니다.
  취소는 `self._cancelled` set으로 **다음 글 전에만** 반영됩니다.
  `BLOCKING_RESULT_CODES = {"captcha_required", "login_required"}`만 배치를 중단합니다.
- `application/automation/governor.py`의 `SafetyGovernor`가 글마다 실행 **전에** 판정하고 실행
  **후에** 집계합니다. 상한을 넘긴 동작이 먼저 일어나지 않습니다. 날짜는 `Asia/Seoul` 기준입니다.
- `application/automation/schedule_sessions.py`의 `ScheduleSessions`가 무인 실행을 결정합니다.
  gate 3개(schedule mode, 동의, safety policy **저장 여부**)를 모두 통과해야 합니다.
  `SqliteSessionRepository.created_on(day, trigger)`로 하루 한 번만 시작합니다.
- 기존 discovery scheduler 루프(60초 주기)에 `run_scheduled_session_if_due()`가 붙어 있습니다.

### 5.2 참고할 구현 패턴

- `application/llm/budget.py`의 `CallBudget` — "설정 읽기 + ledger 집계 + stable code 예외"
- `run_engagement.py`의 `monotonic` 주입 — fake clock 패턴
- `application/discovery.py`의 `SmtpDigestSender` — 알림 발송
- `api/factory.py` — **매우 큰 단일 파일**입니다. 배선 추가 시 `register_*_routes` import 목록,
  `application.automation` import 목록, 인스턴스 생성 위치, lifespan shutdown 호출을 모두
  갱신해야 합니다.

### 5.3 Client SPA

- `client/src/app/main.ts`가 `createWorkspace(root)`로 4개 controller를 조립합니다.
- navigation은 `#workspace` **밖** shell(`client/public/index.html`)에 있습니다. 모든 view가
  render 시 root를 비우므로 안에 두면 사라집니다.
- focus 이동(`focusWorkspace`)은 **화면 전환에서만** 합니다. 매 render마다 하면 입력 중 focus를
  빼앗습니다.
- SSE 구독은 `api/run-stream.ts`(단건)와 `api/session-stream.ts`(배치)로 나뉩니다. 종료 이벤트를
  보면 source를 닫아야 합니다. 닫지 않으면 `EventSource`가 끝난 작업에 영구히 재연결합니다.

  fallback 경로는 CI에서 검증되지 않습니다.

## 9. 규칙

- 생성물(`page.js`, `dist/`, coverage)은 커밋하지 않습니다.
