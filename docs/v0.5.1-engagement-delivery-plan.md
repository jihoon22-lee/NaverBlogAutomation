# v0.5.1 사용자 승인형 교류 자동화 Delivery Plan

Status: Accepted implementation plan, 2026-07-27

이 문서는 사용자가 선택한 네이버 블로그 글 한 건에 대해 공감, 승인된 댓글 등록, 선택적
서로이웃 신청을 처리하는 v0.5.1 작업의 범위와 완료 조건을 고정합니다. 구현 상태는 연결된 GitHub
issue의 체크리스트로 추적하며, 모든 항목이 확인되기 전에는 릴리스를 완료로 판단하지 않습니다.

Tracking: [GitHub issue #35](https://github.com/jihoon22-lee/NaverBlogAutomation/issues/35)

## 목표 사용자 흐름

### 이웃 새 글

1. 사용자가 **오늘의 작업 > 이웃 새 글**에서 글 한 건을 선택합니다.
2. extension이 글을 열고 로딩 완료 후 본문 preview를 표시합니다.
3. 사용자가 댓글 후보를 생성하고 하나를 선택하거나 편집합니다.
4. **공감하고 댓글 등록**을 누릅니다.
5. 실행될 글, 댓글, 공감·댓글 작업을 마지막 확인 화면에서 검토하고 승인합니다.
6. extension은 공감 상태를 확인해 필요한 경우에만 한 번 누르고, 승인된 댓글을 한 번 등록합니다.
7. 단계별 결과를 표시하고 성공한 글을 대기열에서 완료 처리합니다.

### 신규 이웃 후보

1. 사용자가 **오늘의 작업 > 신규 이웃 찾기**에서 후보 글 한 건을 선택합니다.
2. 본문 확인과 댓글 선택까지 이웃 새 글과 같은 흐름을 따릅니다.
3. **교류하고 서로이웃 신청**을 누릅니다.
4. 사용자는 공감, 댓글, 서로이웃 신청 메시지를 마지막 확인 화면에서 검토하고 승인합니다.
5. extension은 공감, 댓글 등록, 현재 이웃 관계 확인, 서로이웃 신청을 순서대로 실행합니다.
6. 이미 성공했거나 불필요한 단계는 건너뛰고 결과를 저장합니다.

## 변경할 수 없는 실행 원칙

- 자동 외부 동작은 사용자가 마지막 확인 화면에서 승인한 글 한 건에만 실행합니다.
- 대기열 전체, 여러 탭 또는 여러 계정을 일괄 실행하는 기능은 이 버전 범위에 포함하지 않습니다.
- 댓글은 사용자가 선택하거나 편집한 최종 text만 등록합니다.
- 공감과 서로이웃은 현재 상태를 먼저 읽고 이미 완료된 경우 클릭하지 않습니다.
- DOM 대상이 없거나 둘 이상이면 추측해 클릭하지 않고 사용자에게 원인을 표시합니다.
- 댓글 등록 결과가 불명확하면 자동 재등록하지 않습니다.
- 성공한 단계는 저장하며 재시도 시 반복하지 않습니다.
- Captcha, 재로그인, 운영 제한을 우회하지 않습니다.
- 약관 고지 버전이 바뀌면 기존 동의를 그대로 재사용하지 않습니다.
- 계정 정보, cookie, 원문, 댓글, 비밀값은 log·screenshot·GitHub artifact에 남기지 않습니다.

## 공통 작업 규칙

각 PR은 다음 규칙을 모두 지킵니다.

- task branch에서 작업하고 `main`에 직접 push하지 않습니다.
- Conventional Commit으로 기능과 문서 변경을 적절히 나눕니다.
- 관찰 가능한 동작 변경에는 단위 또는 통합 테스트를 함께 추가합니다.
- 환경 설정이나 사용 방법이 바뀌면 같은 PR에서 관련 문서를 갱신합니다.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv run ty check`,
  `uv run pytest`, `npm --prefix extension run check` 중 변경 범위에 해당하는 로컬 검사를 수행합니다.
- PR은 review 가능한 상태로 열고 required CI가 모두 통과한 뒤 병합합니다.
- 한 PR이 병합된 뒤 GitHub checklist와 이 문서의 검증 기록을 갱신하고 다음 PR을 시작합니다.
- 계획 변경이 필요하면 구현 전에 이유, 대체 범위, 영향받는 체크 항목을 사용자에게 알립니다.

- [ ] GitHub tracking issue의 모든 구현·검증 체크박스가 체크되어 있다.
- [ ] PR 1~7이 required CI 통과 후 순서대로 병합되어 있다.
- [ ] `main` working tree와 origin이 일치하고 tracked 변경이 없다.
- [ ] v0.5.1 tag가 의도한 main commit을 가리킨다.
- [ ] GitHub Release가 draft/prerelease가 아니며 asset 3개가 정상 업로드됐다.
- [ ] 실제 사용자 흐름 두 가지가 계획과 같은 순서로 동작한다.
- [ ] 성공한 외부 동작의 중복 실행 방지와 불명확 결과의 안전 중단이 검증됐다.
- [ ] 문서가 실제 UI, 환경 변수, 오류 복구 방식과 일치한다.
- [ ] 작업 중 만든 임시 파일을 목록으로 확인한 뒤 승인된 대상만 정리했다.
